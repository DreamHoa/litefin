Development priorities
1. Validate Emby authentication, media browsing and playback reporting.
2. Validate embedded and external text and bitmap subtitles separately.
3. Verify redirects, HTTP byte ranges, seeking and recovery on the target.
4. Test audible HTML5 speed changes with compatible SDR content. Record
   pitch, actual channel output, smoothness and subtitle synchronization.
5. Validate native AVPlay HDR and multichannel playback before UI pruning.
6. Add content-based backend selection only for verified combinations,
   with manual override and playback-state recovery on fallback.
7. Measure responsiveness and runtime memory before simplifying features.

Subtitle architecture notes from the pinned upstream source
- MediaHelper.getSubtitleUrl constructs a server extraction URL when a
  subtitle has no DeliveryUrl; SubtitleManager._loadPGSTrack uses that URL.
- PGSRenderer accepts a subtitle URL. External subtitle chunk downloads
  are not proof of direct Matroska subtitle extraction.
- Native Tizen embedded-text delivery and client-rendered PGS follow
  different paths; test track mapping and data availability independently.
- A server extraction failure must be distinguished from parsing, worker,
  canvas and timing failures. Successful decoding requires subtitle bytes.
- Test first/continuous cues, forward/backward seeks, track changes,
  disabling subtitles, re-entry, clock synchronization and cleanup.
- Passing tests or matching deployed file hashes do not replace visible
  subtitle acceptance on hardware.

Repository privacy

- Use ignored .local/ and diagnostics/ directories for local evidence.
- Preserve upstream licensing and attribution.

Candidate build 20261114.1
- Send the session token header before server-type discovery completes, so
  cold starts and language reloads do not reject saved Emby sessions merely
  because the server has not yet been identified.
- Normalize HDMV_PGS_SUBTITLE and support indexed Matroska subtitle reads
  when DirectPlay media lacks a server-provided subtitle delivery URL.
- PGS renders decoded bitmap cues on a canvas; SubRip renders text cues.
  The embedded ASS fallback renders dialogue text without full ASS styling.
- MKV readers are adapted from Moonfin under MPL-2.0, with attribution in
  each file. The decoder dependency is pinned to fflate 0.8.3.
- Full suite: 1126 tests passed. Modified-file lint and Modern packaging
  passed. Hardware playback and session-persistence acceptance are pending.
- Optional local diagnostics (bu8000:diagnostics) expose playback counters
  and controls, without exposing the player instance or authentication data.

Baseline build 20261114.4-baseline
- PGS reading is aligned with the first working Moonfin reader, retaining
  only the Litefin fetch/logging adapter. Speculative epoch backtracking,
  block-size tuning and batch-size tuning have been removed.
- A controlled single-block HTTP 503 test verifies that valid subsequent
  subtitle blocks are still delivered; an infinite per-cue retry must not
  stall the entire batch. This reproduces a failure mechanism rather than
  claiming it proves every earlier on-device failure.
- Text-track Range handling cancels and retries a transient full-file 200
  response without consuming the full media file.
- Complete suite: 1128 passed; Modern build and packaging passed.

Candidate build 20261114.7-ranges
- The first Moonfin reader is a baseline, not a drop-in acceptance result.
  Keep its bounded retries; remove the second reader's infinite per-cue retry.
- A real libpgs 0.8.1 open-stream regression proves decoded timestamps may
  remain unpublished when progress callbacks are throttled. The adapter
  publishes the first parsed timeline without waiting for another HTTP batch.
- Deliver ready compositions in timestamp order, rather than withholding
  all current subtitles until the entire lookahead batch has completed.
- Hardware traces show high per-request latency. A bounded 32 KiB probe
  and reuse of the validated starting composition remove duplicate reads.
  Tests verify byte preservation for both 20 KB and 60 KB compositions,
  including exact oversized tails; full-file HTTP 200 remains refused.
- Hardware PGS acceptance is partial: continuous bitmap drawing and recovery
  after an uncached backward seek are confirmed with changing image hashes.
  Cold track selection still took about 14 seconds, and uncached backward
  recovery about 16 seconds. These delays remain open, not passed.
- ASS is dialogue-only fallback; complete ASS styling is not implemented.
- Full suite: 1132 passed; changed-file lint and Modern packaging passed.
  Private hardware traces and credentials are excluded from this repository.

Build 20261114.8-cache: minimal PGS Range cache fix
- The only playback behavior change is cache: 'no-store' on indexed PGS
  range requests. Cacheable same-resource requests serialized on the TV,
  defeating the existing reader's four-way concurrency.
- Same-target hardware A/B with both starting timelines ready: default
  requests needed 7.421 seconds of subtitle data catch-up after native seek;
  no-store needed 1.776 seconds. Earlier trials independently reproduced it.
- Installed signed build, with no runtime cache override: +10-second seek
  had zero additional subtitle data wait after landing. A large forward seek
  needed 0.841 seconds of additional data wait (4.362 seconds to first bitmap,
  including native seek). Unbuffered backward seek needed 3.521 seconds of
  extra data wait, with first bitmap at 6.796 seconds; this cost remains.
- The actual first Moonfin signed package was inspected, including its reader,
  canvas adapter and Tizen call site. It also used default fetch caching.
  Its extensionless Emby URL returned the same bytes and still serialized
  default Range requests in the same-device control; changing URL shape was
  rejected as the fix. Yesterday's unmeasured latency is not claimed known.
- Complete suite: 1132 passed; changed-file lint and Modern packaging passed.
  Hardware timings include sampling uncertainty and are not universal SLAs.
